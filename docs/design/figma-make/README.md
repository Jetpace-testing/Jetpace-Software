# Figma Make export — "Ocean Blue Sensor Dashboard"

**Reference material. None of this is built, imported, or on any code path.**

Generated by Figma Make from a brief plus the Donezo screenshot, then
rebranded to Jetpace. Kept here because `src/index.css` and `src/App.tsx`
are a far more precise statement of the intended design than a screenshot,
and because the information architecture in them is genuinely good.

## Why it cannot be imported as code

It is **React 19 + Vite 8 + Tailwind v4 + TypeScript**. This product is
FastAPI + Jinja + HTMX + ECharts with **no JavaScript build step**, because
it has to run on a plant network with no route to the internet — which is
also why every asset is vendored. Adopting this source means adopting Node,
a bundler and a build pipeline, against a convention in CLAUDE.md.

`src/index.css` also opens with an `@import` of Inter from Google Fonts.
We vendor Inter locally for the same offline reason — see
`packages/core/.../static/vendor/README.md`.

## The instruction files were renamed on purpose

The export shipped a `CLAUDE.md` containing `@AGENTS.md`, and an
`AGENTS.md` telling an agent to use Tailwind utility classes and that a
Vite dev server is already running on port 8443. All true of *that*
project and wrong for this one. A file that tells Claude Code how to work,
sitting inside this repository, contradicting its actual conventions, is a
trap for whoever reads it next — so `AGENTS.md` is kept as
`AGENTS.md.txt` for reference and `CLAUDE.md` was not copied at all.

## What was measured, before taking anything from it

Run against the data-viz validator rather than judged by eye:

| | |
|---|---|
| `#087ea4` carrying white text | 4.64:1 — passes, just |
| `#087ea4` as text on its own tint `#e6f4fa` | **4.12:1 — fails** |
| `--muted` `#718096` on white | **4.02:1 — fails** |
| All six status badges, as actually used | **3.41–4.47:1 — fail** at the sizes they are set in |
| Their navy on our dark surface | **1.27:1** — there is no dark mode in this design at all |

And the type scale: **57 declarations at 10px or smaller** — fourteen at
7px, sixteen at 8px — with nothing larger than 23px. Table rows and status
badges are 8px. That is a composition tuned to look dense and impressive
as a preview image, not to be read by someone standing at a plant PC.

## So what is worth taking

The **information architecture**, which is the expensive part to invent:

- seven KPIs rather than four, and which seven
- the live table's columns — device, location, temp, humidity, differential
  pressure, connectivity, alarm, last update
- a system-health block pinned to the bottom of the sidebar
- an alarm count badge on the nav item
- filter row above the table: search, room, device, alarm state
- the facility floor plan with sensor markers, which we have no analogue for

Taken as layout and hierarchy, expressed in our own tokens and type scale —
the same way the Donezo reference was used. See `../frontend-plan.md`.
