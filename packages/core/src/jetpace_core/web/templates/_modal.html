There is no write path in this application at all - queries.py says so in its first paragraph, and the database grants the application role append-only on `reading` and nothing on `device`. A form that collects three fields and then cannot save them is the worst thing to put in front of a customer, because they will fill it in. So the chrome is the design's, exactly, and the content is the real route: a device is commissioned from the gateway sheet by the provisioning step. That is genuinely what somebody asking "how do I add a meter" needs, and it is one click from where they asked. Device management

Commissioning a device

Devices are not created here. This dashboard only reads — the application's database role has no write grant on the device tables — so a new instrument arrives the same way the existing ones did, from configuration.

1 · Add it to the gateway sheet
Its code, name, gateway, Modbus unit address and model go in config/prototype.toml, beside the devices already on that bus.
2 · Provision
Run the provisioning step. It creates the device row, pins it to the model revision its register map was written against, and records when it was commissioned.
3 · It appears
The poller picks it up on its next pass and the table above shows it, offline, until the first reading arrives.
